Your stack

strawberry-graphql/strawberryStrawberry 0.326.1 → 0.327.7

Upgrade for 0.326.1 if you use custom permissions (GHSA-pfvf-fwfp-25mp): if has_permission was a plain def that returned an awaitable, Strawberry treated it as a sync check, and an awaitable is always truthy. So protected fields with sync resolvers were served even when the check resolved to False. The fix fails closed, so write async checks as async def. In the same run, 0.327.0 caps the ParserCache/ValidationCache extensions at 128 entries. They used to be unbounded, which let anyone send distinct queries to grow server memory. 0.327.2 also frees legacy graphql-ws subscription slots when a subscription finishes. Note 0.326.0: custom schema directives now show up in introspection, and schema construction now errors on directive name clashes.

hashicorp/terraformTerraform 1.17.0-beta1, 1.16.1, 1.16.2

The 1.17 beta adds variables and locals inside provider requirements and a new -minimal-refresh plan option that only refreshes resources with proposed changes, which is a big time saver on large states. Terraform Policy is now GA, so -policies no longer needs the experimental flag. The 1.16 patches are worth taking now if you adopted the new import features: 1.16.1 fixes import blocks being silently ignored when several targeted different for_each/count instances, plus a create_before_destroy ordering bug and a few panics. 1.16.2 fixes a panic during module installation.

hasura/graphql-engineHasura 2.50.3

A memory-focused patch. Updating metadata (for example with replace_metadata) used to keep the startup schema in memory, which could double memory use. That is fixed. The new bounded websocket queues also changed behaviour: a write to a full queue now returns an error for that operation and cancels the subscription instead of evicting messages. HASURA_GRAPHQL_WEBSOCKET_QUEUE_SIZE was being silently ignored and now works. The ..._evicted_total metric is replaced by hasura_websocket_messages_dropped_total, so update any dashboards or alerts that used it.

mapbox/mapbox-gl-jsMapbox GL JS 3.30.0 (+ 3.31.0-rc.1)

Breaking: pitch and rotation are now independent. Before, disabling rotation also disabled pitch, so maps that turned off rotation to "lock" the view may now let users tilt them. Check your interaction setup. Also new: client-side overzooming for raster-array sources, up to 64 sources per style, Supercluster v9 (less clustering memory), terrain split out of the core ESM module, and an animationFrameProvider option to drive the render loop externally. The 3.31 RC significantly reduces GeoJSON memory use, which matters for big vector overlays, and raster-allow-draping is no longer experimental.

PrefectHQ/prefectPrefect 3.8.5

Mostly reliability fixes for self-hosted orchestration. Scheduled flow-run polling is fixed, deployment concurrency leases now hold across flow retries (before, a retry could let another run take the slot), and a SIGTERM that arrives after completion no longer marks a finished run as Crashed. On the server, flow-run cleanup is now indexed and orphans are reconciled separately. The event persister also uses less CPU on INSERTs. Small but welcome: importing prefect.cache_policies no longer pulls in pandas.

astral-sh/uvuv 0.12.8 → 0.12.13

Six releases, mostly supply-chain hardening. macOS and Windows binaries and the uv wheels are now code-signed, so publisher-based allowlisting works and antivirus false positives should drop. Source archives are now checked against uv.lock hashes before their metadata is read or their build backend runs, and PEP 658 metadata sidecars are hash-checked too. Credentials are stripped on redirects that cross auth realms. exclude-newer now correctly leaves out distributions uploaded after the cutoff. There are also several install-speed improvements, CPython 3.15.0rc2, and new --no-locked/--no-frozen flags to override UV_LOCKED/UV_FROZEN for a single command.

GIS world

postgis.netPostGIS 3.7.0rc2

The last release candidate before 3.7.0, out 8 September. It adds more robustness and WKB/TWKB parsing security fixes on top of rc1. Now is a good time to check your code against the breaking changes: PostgreSQL 12–13 and GEOS < 3.10 are dropped, topology functions read tolerance 0 differently (use -1 for "topology precision"), ST_MemCollect is removed, CG_AlphaShape returns a MultiPolygon, and address_standardizer/tiger_geocoder moved to separate repos. New: a minimum-spanning-tree window function, ST_XSize/ST_YSize-style helpers, MultiLineString input for ST_MakeLine, and Float16 raster pixels.

cloudnativegeo.orgPortolan: a serverless spatial data infrastructure

A new open spec and toolkit for publishing a whole SDI as files in an object-storage bucket, with no server or database. It uses GeoParquet and PMTiles for vectors, COGs for rasters, and STAC to organise everything, with Zarr and COPC planned. Tooling includes a CLI for ingest, conversion and publishing, a validator (Rashid) with agent-friendly JSON output, and agent skills that run the full workflow. A good reference design if you serve read-mostly catalogs through API servers today.

apache/parquet-formatParquet format 2.14.0 adds ALP float encoding

The spec release that makes ALP (Adaptive Lossless floating-Point) encoding official, marked "preview": the spec is stable, but readers and writers are still adding support. ALP targets data that Parquet's older encodings compress badly: doubles and floats such as sensor readings, and especially coordinates. It works by scaling floats to integers, then bit-packing them. Nothing to change yet, but watch for it in DuckDB, Arrow and GDAL if you store lots of lat/lon or measurement columns in Parquet. The release also adds a FILE logical type and defines how readers should handle unrecognised logical types.

Worth knowing

digital-strategy.ec.europa.euEU Cyber Resilience Act reporting went live on 11 September

If you ship software sold in the EU, you must now report actively exploited vulnerabilities and severe incidents through ENISA's Single Reporting Platform: an early warning within 24 hours, a full notification within 72 hours, and a final report within 14 days of a fix. This covers products already on the market. It also covers exploited flaws in third-party components inside your product, such as a compromised dependency. Non-profit open-source projects are exempt, and open-source "stewards" only have to report from December 2027. In practice, you need an on-call path from "a dependency is being exploited" to a filed report.

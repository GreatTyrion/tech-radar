# Tech digest — 2026-08-29

Window: 2026-08-16 → 2026-08-29.

A busy fortnight with two genuine headliners: **Terraform 1.16.0 went GA**, and **DuckDB published a v2.0 preview** that turns the embedded database into something you can also run as a server. On the GIS side, a pre-auth SQL injection in GeoTools' PostGIS data store is being actively exploited — patch first, read the rest after. Also shipped and not detailed below: Vite 8.2.2 (HMR through circular imports, Lightning CSS empty-targets fix), Strawberry 0.324.1–0.324.4 (`strawberry.field()` inside `Annotated` now works on object, input and interface types; Python 3.15 support), and tipg 1.5.0 (an optional Prometheus metrics endpoint).

## Your stack

### Terraform 1.16.0 — `hashicorp/terraform`
The RC we flagged last time is now stable. The headline items for most people: **`import` blocks finally work inside modules** instead of root-only, `lifecycle { destroy = false }` as a softer `prevent_destroy` that blocks destruction without failing the plan, and machine-readable `terraform state show -json` / `terraform workspace list -json`. Also handy: `terraform console -scope=<module address>` to evaluate expressions inside a module, `terraform graph -format=mermaid`, and `contains()` can now test for null. One upgrade note worth reading before you go: `bastion_host_key` is now *correctly* applied by provisioners, so verify the configured key is actually right if you use SSH provisioners.
📎 [v1.16.0 changelog](https://github.com/hashicorp/terraform/releases/tag/v1.16.0)

### DuckDB v2.0 preview — `duckdb/duckdb`
More than 10,000 commits since 1.5, with GA targeted for autumn 2026. The big architectural shift is a **stable Quack protocol**: you can `ATTACH` a remote DuckDB server and run queries against it, with pushdown to PostgreSQL and MySQL. For analytics over object storage the more immediately useful change is **async I/O across Parquet, CSV and the native format**, plus wider row-group pruning — both aimed squarely at network-backed scans. Also in: triggers, a much stronger `VARIANT` type with shredded execution, NEAREST joins, a new PEG-based SQL parser, ICU dropped in favour of native timezone handling, and a **versioned C API with ABI guarantees** so extensions stop breaking on every release. There are deliberate breaking changes around the storage format and lambda syntax, so treat this as a "start testing" signal rather than an upgrade.
📎 [A Preview of DuckDB v2.0](https://duckdb.org/2026/08/17/duckdb-20-highlights)

### Argo CD 3.5.2 / 3.4.8 — `argoproj/argo-cd`
A small patch round, but two of the fixes matter operationally. **Auto-sync was being skipped when a newer commit landed mid-sync** — if you have ever seen a commit silently not deploy and had to nudge it manually, that is the bug. The other is a controller crash: Argo CD now recovers from a kubectl panic in `AuthReconcile` when the service account is forbidden, rather than taking the reconcile down with it. There is also an ApplicationSet fix restoring `ignoreApplicationDifferences` after normalization, and notification-controller fixes (deep-copy before mutating shared-cache objects, read AppProjects from the informer cache). Dex bumped to 2.45.1.
📎 [v3.5.2 release notes](https://github.com/argoproj/argo-cd/releases/tag/v3.5.2)

### Mapbox GL JS 3.29.0 — `mapbox/mapbox-gl-js`
A real feature release. The one to know if you render raster analysis output: **`raster-color-scale`**, which can be set to `"log"` to get usable colour-ramp precision on long-tailed datasets — the classic problem with radar backscatter and other heavily skewed rasters. There is also `raster-allow-draping: false` to opt a raster layer out of draping over globe/terrain, `symbol-z-offset` promoted out of experimental, and the `distance` expression now accepts an expression as its second argument. Interaction handlers get much finer control — `map.keyboard`, `map.dragRotate` and `map.touchZoomRotate` gained per-capability enable/disable methods, and **`isEnabled` changed from AND to OR semantics**, which is a behaviour change if you branch on it. Breaking: the undocumented legacy `Map.addSourceType` API is gone. The 3.30.0 RC that followed makes pitch independent of rotation and raises the source limit per style to 64.
📎 [v3.29.0 release notes](https://github.com/mapbox/mapbox-gl-js/releases/tag/v3.29.0)

### GDAL 3.13.3 — `OSGeo/gdal`
Bug-fix release with a couple of pointed fixes. The COG driver had a **multithreading bug in `BuildOverviews()` across multiple bands** — relevant to anyone generating COGs in a parallel pipeline. The ENVI driver's multiband BSQ handling is fixed for band offsets beyond `INT_MAX`, a regression introduced in 3.12.2, and the Unix port fixes a file-read buffering regression that dates back to 3.13.0. Security-adjacent: an integer overflow in the DOQ2 driver, null-pointer dereferences in the GDALG and Zarr drivers, and picked-up libgif patches.
📎 [GDAL 3.13.3 release notes](https://github.com/OSGeo/gdal/releases/tag/v3.13.3)

### Hasura 2.50.1 — `hasura/graphql-engine`
Three things worth having. New opt-in flags **redact request bodies, session variables and webhook responses from delivery logs** for event triggers, scheduled/cron triggers and action handlers (`HASURA_GRAPHQL_REDACT_EVENT_TRIGGER_LOGS` and friends, all default off) — a straightforward win if PII flows through your triggers. **Caching now fails open**: a query with `@cached` no longer 400s when Redis is unavailable, it just executes uncached, matching how rate limiting already behaved. And a v2.50.0 regression that **broke SSO login to the Console** (hung at "Validating…") is fixed — the `jwt-decode@4` migration had changed the decoded-token shape. The bundled data connector also picks up fixes for two HIGH-severity micrometer DoS CVEs.
📎 [v2.50.1 changelog](https://github.com/hasura/graphql-engine/releases/tag/v2.50.1)

### Prefect 3.8.4 — `PrefectHQ/prefect`
Mostly small, but a few things you would want. There is now an **index on `flow_run.deployment_id`**, which is a meaningful query-time improvement on a self-hosted server with a lot of history. Workers stop ignoring a `prefetch_seconds` of 0, and runners no longer overwrite an already-handled flow-run outcome — the kind of bug that turns a clean failure into a confusing one. `ProcessWorker`'s auto-uv behaviour after pull steps is fixed. On the packaging side, the sdist was accidentally being shipped inside the published server and client images and is now bind-mounted out, so the images get smaller.
📎 [3.8.4 release notes](https://github.com/PrefectHQ/prefect/releases/tag/3.8.4)

### uv 0.12.6 → 0.12.7 and Ruff 0.16.4 → 0.16.5 — `astral-sh`
uv rounds out **profile-guided optimization across all four major release targets** (Linux x86-64 and ARM64, Windows x86-64, macOS ARM64), and closes a supply-chain-shaped hole: source archives with **hash mismatches are now rejected before their extracted contents hit the cache**, rather than after. Managed Python installs are now replaced when upgrading to a newer build of the same version, and a batch of resolver fixes land around recursive extras and full 40-character Git commit pins. Ruff's changes are mostly incremental — new syntax-error detection for duplicate keyword arguments and parameters declared `nonlocal`, an autofix for `PTH116`, and a fix for `InvalidInstruction` crashes on older Windows CPUs without POPCNT. Preview is where the interesting work is: **category selectors** and rules without codes, both reshaping how rule selection will work.
📎 [uv 0.12.7](https://github.com/astral-sh/uv/releases/tag/0.12.7) · [Ruff 0.16.5](https://github.com/astral-sh/ruff/releases/tag/0.16.5)

## GIS world

### GeoTools / GeoServer pre-auth SQL injection, actively exploited — `GHSA-mqjf-5f49-2fjh`
Patch this one. The `jsonArrayContains` filter function in GeoTools writes its `<value>` argument into generated SQL **without escaping**, so any OGC filter evaluated against a PostGIS data store is an unauthenticated SQL injection — CVSS 9.8, and reported to escalate to RCE under some configurations. Disclosed publicly on 12 August, with internet-wide probing starting within hours and a botnet joining shortly after. Fixed in GeoTools 35.1 / 34.5 / 33.6 and GeoServer 3.0.1 / 2.28.5 / 2.27.6, released 14 August. The trap: this is a **regression of CVE-2023-25158, and the 2023 mitigation does not close it** — enabling prepared statements and disabling function encoding is not enough, so teams who applied that guidance and consider it settled are still exposed. If you expose any GeoServer/GeoTools-backed OGC endpoint, upgrade rather than mitigate.
📎 [GeoTools security advisory](https://github.com/geotools/geotools/security/advisories/GHSA-mqjf-5f49-2fjh)

### Overture Maps 2026-08-19 release — `overturemaps.org`
Data release `2026-08-19.0` on schema v1.18.0. The change to plan for is a **deprecation: the `categories` property in places is being replaced by `basic_category` and `taxonomy`, with both available only through September 2026** — so if you consume places categories, you have roughly a month to migrate. Data-wise: buildings gained 13.09M features from Microsoft ML and 3.81M from OSM (net −0.61% after removals), with better floor-count and height attribution; base infrastructure grew 1.80% including parking and transit; transportation added 5% more TomTom segments with wider `road_surface` and access-restriction coverage; and addresses (still alpha) is close to 473M records. Everything is indexed through Overture's STAC catalog, which now points at this release.
📎 [2026-08-19 release notes](https://docs.overturemaps.org/blog/2026/08/19/release-notes/)

## Worth knowing

### npm 12 blocks install scripts by default — `github.blog`
Worth surfacing if your JS toolchain has not moved yet: since npm 12, **dependency `preinstall`/`install`/`postinstall` scripts do not run unless a project explicitly allows them**, and that includes implicit `node-gyp` builds for any package with a `binding.gyp`, even with no declared script. This will break CI for native-dependency builds until you run `npm install-scripts approve` and `npm rebuild`. The urgency behind it is the CHAINDROP worm that compromised the `keyv` maintainer's account earlier this month and self-propagated to 400+ packages totalling well over a billion monthly downloads — it spread specifically through a `preinstall` hook. The migration path has been available behind warnings since npm 11.16.0, so upgrading is mostly a matter of recording approvals before the CI break rather than after.
📎 [Upcoming breaking changes for npm v12](https://github.blog/changelog/2026-06-09-upcoming-breaking-changes-for-npm-v12/)

# Tech digest — 2026-08-05

Window: 2026-07-27 → 2026-08-05.

A release-heavy nine days on the tooling side: uv shipped its first breaking release since March, Argo CD 3.5 landed with a Helm 4 upgrade, and Hasura patched an authorization bug. Quiet on the geospatial-news front — two items worth a look, no filler.

## Your stack

### uv 0.12.0 → 0.12.2 — `astral-sh/uv`
The first breaking release since 0.11 in March, bundling up accumulated correctness and safety changes. Most users should upgrade cleanly, but read the list: `uv init` now **declares a build system by default** (`uv_build`, `src/` layout, a `[project.scripts]` entry) — use `--no-package` for the old unpackaged layout. Pre-release handling changed to `if-necessary`, so uv tries stable candidates first and can now resolve pre-release requirements discovered transitively, which means it may pick different versions than before. Several supply-chain hardening changes cannot be opted out of: non-`.tar.gz` sdists and bzip2/LZMA/XZ-compressed wheel entries are rejected, wheels that could overwrite the interpreter (`Python.exe`, `.data/data/bin/python`) are blocked, `--require-hashes` inside a `requirements.txt` is finally honoured rather than warned about, and MD5-only hashes no longer satisfy hash-checking mode. If you pin `uv_build` in `[build-system]`, widen the bound to `<0.13`.
📎 [uv 0.12.0 release notes](https://github.com/astral-sh/uv/releases/tag/0.12.0)

### Argo CD 3.5.0 — `argoproj/argo-cd`
The upgrade notes matter more than the feature list here. Argo CD now bundles **Helm 4.2.1**, which enforces stricter OCI handling — plain-HTTP OCI registries need `--insecure-oci-force-http`, including for chart dependencies, and there's a known bug where combining it with `--insecure-skip-server-verification` silently drops the HTTP flag. The UI moved to **React 19**, so custom UI extensions must be rebuilt to externalize `react/jsx-runtime` or they fail to load. Event-listing gRPC methods now return an Argo CD–defined `EventList` type, so custom gRPC clients need regenerating (REST is unaffected). On the plus side: impersonation now covers logs, deletes and actions rather than just syncs — check your RBAC before upgrading. GnuPG signature verification is replaced by a new Source Integrity subsystem.
📎 [3.4 → 3.5 upgrade guide](https://argo-cd.readthedocs.io/en/stable/operator-manual/upgrading/3.4-3.5/)

### Hasura v2.50.0 (and v2.45.8 LTS) — `hasura/graphql-engine`
Contains a security fix flagged **IMPORTANT** by the maintainers: a bug in the MS SQL Server backend could, in certain cases, let an authenticated user observe data they weren't authorized for. Only relevant if you use the mssql backend, but worth knowing about. Two other changes affect everyone: the September-2023 naming convention is **no longer the unconditional default** — that earlier change was a breaking one for OSS/EE users and it's back to opt-in via `HASURA_FF_NAMING_CONVENTION_SEP_2023`. And event trigger names now get strict validation (alphanumeric, underscore, hyphen only) — existing metadata keeps working, but non-conforming names will block your next `replace_metadata`. New `HASURA_GRAPHQL_DISABLE_ADMIN_SECRET` lets you force webhook/JWT auth by ignoring the admin-secret header entirely.
📎 [v2.50.0 release notes](https://github.com/hasura/graphql-engine/releases/tag/v2.50.0)

### FastAPI 0.140.1 → 0.141.1 — `fastapi/fastapi`
A dense week of small releases with two useful threads. First, a run of **memory and OpenAPI-generation refactors** — dependency trees are no longer flattened and retained, repeated flattening during OpenAPI generation is gone, and the dependency `lru_cache` limit was raised for large apps. If you have a big router tree, this is a free win. Second, several **streaming fixes**: `status_code` was being ignored for SSE and JSONL endpoints, `format_sse_event` didn't split lines per the SSE spec, and stream item types were lost through `include_router()`. Also new: `app.frontend(check_dir="auto")` for smoother local dev under `fastapi dev`.
📎 [0.141.1 release notes](https://github.com/fastapi/fastapi/releases/tag/0.141.1)

### Mapbox GL JS v3.28.0 — `mapbox/mapbox-gl-js`
One breaking change: `text-variable-anchor` is **disabled when appearances are present** — check your label placement if you've adopted appearances, which also lost their experimental flag this release. `line-border-width` and `line-border-color` are now public paint properties (previously private), with an experimental `line-border-gradient` alongside. New `map.resetFeatureStates()` clears all feature state for a featureset or layer in one call, and `map.getSchema()`/`setSchema()` expose imported-style schema management. Notable for load times: dev/debug code, model code and the `raster-array` layer were split out of the ESM core bundle, plus general size reductions across style, program, symbol and expression code.
📎 [v3.28.0 release notes](https://github.com/mapbox/mapbox-gl-js/releases/tag/v3.28.0)

### Vite 8.2.0 — `vitejs/vite`
Adds a top-level `input` option (and `input` as an implicit `server.fs.allow` entry), with plugin-aware resolution of it. The bundled-dev path keeps maturing: it reloads once after a rebuild instead of routing through the fallback page, supports HMR-accepted worker file updates, and now prints build errors to the terminal when an HMR update fails. Smaller fixes worth having if you hit them: HMR environment snapshots survive a server restart, base is stripped in index.html module-graph lookups, and stack-trace source mapping keeps working when `Object.prototype` is frozen.
📎 [Vite 8.2.0 changelog](https://github.com/vitejs/vite/blob/v8.2.0/packages/vite/CHANGELOG.md)

### pgstac v0.9.12 — `stac-utils/pgstac`
A single-commit release, but a targeted one: fixes for concurrency issues in the schema. If you run parallel ingest or bulk loads against a STAC Postgres catalog, this is the kind of fix that resolves intermittent failures you'd otherwise struggle to reproduce.
📎 [v0.9.12 release](https://github.com/stac-utils/pgstac/releases/tag/v0.9.12)

### Prefect 3.8.1 — `PrefectHQ/prefect`
Bugfix release, but several are operationally meaningful for self-hosted setups. Workers **no longer die at startup when the API is unreachable**, which matters if your worker pods can outrace the server on a cluster restart. Evicted flow runs are now relinquished to infrastructure retry instead of being lost, stale expiration entries are cleared when a repossessed lease goes missing, and subprocesses survive output-stream errors. `FlowRunFilter` now rejects unknown fields, so typo'd filter keys fail loudly rather than silently matching everything.
📎 [3.8.1 release notes](https://github.com/PrefectHQ/prefect/releases/tag/3.8.1)

### Ruff 0.16.1 — `astral-sh/ruff`
Follow-up to last week's big default-rule-set change. Mostly false-positive fixes in the newly-prominent rules — `RET504` no longer fires when the variable is read in a `finally` clause, `B008` treats `range` as immutable, `D214`/`D405`/`D413` skip section detection inside RST directive bodies. Also: fix safety was tightened on several `flake8-pytest-style` and `refurb` rules, and the LSP now lints TOML files. Worth taking if you're mid-upgrade to 0.16.
📎 [0.16.1 release notes](https://github.com/astral-sh/ruff/releases/tag/0.16.1)

## GIS world

### NRO puts commercial SAR on operational contracts — `Breaking Defense`
The US National Reconnaissance Office moved Capella Space, ICEYE US and Umbra from study agreements onto **operational Radar Commercial Augmentation contracts**, with a base period running 1 Aug 2026 – 31 Jul 2027 and two option years through 2029. The framing is the interesting part: the agency says the three vendors have "successfully proven" themselves and the new vehicles carry defined performance thresholds and continuous-improvement goals rather than demonstration terms. A signal that commercial X-band SAR tasking is being treated as sustained infrastructure — relevant if you're evaluating commercial radar sources alongside Sentinel-1 or NISAR.
📎 [NRO issues 3 SAR data providers new contracts](https://breakingdefense.com/2026/08/nro-issues-3-sar-satellite-data-providers-rigorous-new-contracts/)

### Geo-embeddings standardisation gains traction — `cloudnativegeo.org`
IBM, CNG, Clark University and Planet announced a second Geo-Embeddings Sprint (27–28 Oct, Zürich; **applications close 30 August**, travel support available). More useful than the event itself is the progress report: the March sprint produced community recommendations, launched geoembeddings.org and set up a monthly forum, and since then TESSERA and LGND have implemented the proposed standards while Earth Genome shipped embedding products using the **new STAC extension** for embeddings. If you catalog imagery with STAC, there's now a standard-shaped way to carry learned embeddings alongside it — worth tracking even if you're not doing ML on imagery yet.
📎 [Announcing the Next Geo-Embeddings Sprint](https://cloudnativegeo.org/blog/2026/07/announcing-geo-embedding-sprint-zurich/)

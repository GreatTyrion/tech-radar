# Tech digest — 2026-08-16

Window: 2026-08-05 → 2026-08-16.

The big one this window is outside the repo list: PostgreSQL shipped a 28-CVE security release across every supported branch, and three of the bug fixes need manual reindexing afterwards. Otherwise a quiet patch fortnight — Argo CD and Prefect follow-ups, steady uv and Ruff releases, and a Terraform 1.16 release candidate.

## Your stack

### Argo CD 3.5.1 / 3.4.7 / 3.3.14 — `argoproj/argo-cd`
The 3.5.0 follow-up, backported to all three supported minors, and the fixes lean security-adjacent. Two of them stop secret values leaking through the diff path: the server-side-diff CLI could be tricked into spoofing the secret mask, and secrets were still visible inside the `last-applied-configuration` annotation. There's also an ApplicationSet fix for progressive sync spinning in a tight reconcile loop, and controller fixes so `timeout.reconciliation=0` is properly treated as "soft expiry disabled" rather than "reconcile constantly". If you're already on 3.5, this is a straightforward patch bump.
📎 [v3.5.1 release notes](https://github.com/argoproj/argo-cd/releases/tag/v3.5.1)

### Prefect 3.8.2 → 3.8.3 — `PrefectHQ/prefect`
Two releases of mostly UI polish, with a handful of server-side items worth having. 3.8.3 stops **fragmenting task-run recorder bulk upserts**, which is a real throughput win if you push a lot of task runs at a self-hosted server, and fixes a **leak of watcher-thread timeout enforcers**. Self-hosted setups also get the basic-auth header sent on the events WebSocket handshake — if your events stream was silently failing behind auth, that's the fix. 3.8.2 releases concurrency leases granted to callers cancelled mid-acquire, closing a slow leak of global concurrency slots.
📎 [3.8.3 release notes](https://github.com/PrefectHQ/prefect/releases/tag/3.8.3)

### uv 0.12.3 → 0.12.5 — `astral-sh/uv`
Three non-breaking releases consolidating after the 0.12 break. The theme is **resolver and startup performance**: conflict-heavy resolutions avoid materialised range complements, long runs of unavailable versions get coalesced, Simple API parsing deserialises PyPI metadata directly, and Linux gets faster interpreter discovery by avoiding slow procfs reads. Security-relevant: uv now **prefers post-quantum key exchange** and redacts credentials in requirement URLs when reporting errors. Also new in preview — `uv check --no-install-project` (install deps without building the project, handy in CI), and `--index`/`--default-index` can select a configured index by name.
📎 [uv 0.12.4 release notes](https://github.com/astral-sh/uv/releases/tag/0.12.4)

### Ruff 0.16.2 → 0.16.3 — `astral-sh/ruff`
0.16.3 turns on **profile-guided optimisation for the Linux x86-64, Linux ARM64, Windows and macOS ARM64 release binaries** and switches to mimalloc v3 — free speed in CI, no config change. On the rules side, the `flake8-bandit` shell-injection checks (`S602`, `S603`, `S607`, `S609`) now also inspect keyword arguments, so expect a few new hits if you call `subprocess` with `args=`. Several `pylint` false positives around `%`-formatting are fixed, and `while 1` → `while True` (`UP048`) lands in preview.
📎 [0.16.3 release notes](https://github.com/astral-sh/ruff/releases/tag/0.16.3)

### Terraform 1.16.0-rc1 — `hashicorp/terraform`
Release candidate, so a heads-up rather than an upgrade. The change most people will actually use is `lifecycle { destroy = false }` — a softer `prevent_destroy` that stops a resource being destroyed without failing the plan. Also notable: **`import` blocks now work inside modules** (previously root-only, a long-standing annoyance for modular infra), `terraform state show -json` and `terraform workspace list -json` for machine-readable output, `terraform console -scope=<module address>` for evaluating expressions inside a module, and `terraform graph -format=mermaid`.
📎 [v1.16.0-rc1 changelog](https://github.com/hashicorp/terraform/releases/tag/v1.16.0-rc1)

### Vite 8.2.1 — `vitejs/vite`
Small patch. The one to know about is a **CSS minification fix**: the Lightning CSS visitor was being re-run during minify, which could corrupt output if you use a custom visitor. Also, `server.port: 0` now actually picks a random port instead of misbehaving, and shebangs ending in uncommon line terminators are handled.
📎 [Vite 8.2.1 changelog](https://github.com/vitejs/vite/blob/v8.2.1/packages/vite/CHANGELOG.md)

### Strawberry 0.324.0 — `strawberry-graphql/strawberry`
Adds Django 6.0 and 6.1 support and **drops everything older than Django 5.2 LTS** — 4.2, 5.0 and 5.1 are all end-of-life upstream. No effect if you run Strawberry on FastAPI/ASGI rather than the Django integration, but it will pin your Django floor if you do.
📎 [0.324.0 release notes](https://github.com/strawberry-graphql/strawberry/releases/tag/0.324.0)

## GIS world

### PostGIS 3.7.0beta2 — `postgis.net`
Second beta of the 3.7 line, and the bug-fix list is unusually security-flavoured for a geometry library. Extension install and upgrade SQL is **hardened against attacker-controlled object resolution in writable schemas** (reported by Eric Ridge at PlanetScale) — relevant to anyone who runs `CREATE EXTENSION postgis` in a database where untrusted users can create objects. FlatGeobuf decoding now validates size-prefixed buffers and variable-length property values before reading them, after two separate external reports. Plus memory-leak fixes in `ST_GeometryN` and `ST_DWithin`. Best paired with PostgreSQL 19 Beta 2 and GEOS 3.15.0beta2.
📎 [PostGIS 3.7.0beta2](https://postgis.net/2026/08/PostGIS-3.7.0beta2/)

### Hybrid Icechunk stores for serverless web mapping — `cloudnativegeo.org`
A worked pattern for rendering gridded analysis data (NetCDF, climate/weather stacks) in a browser map **without a tile server and without duplicating the data**. The trick is a "hybrid" Icechunk store: full-resolution data stays as virtual references to the original archival files via VirtualiZarr, and only lightweight multiscale overviews are actually generated, using `topozarr`. The browser reads it with `icechunk-js` and draws it with `zarr-layer`. If you currently stand up a raster tile service purely to preview analysis outputs, this is the serverless alternative worth reading.
📎 [Hybrid Icechunk stores for serverless web mapping](https://cloudnativegeo.org/blog/2026/08/virtual-icechunk-multiscale/)

## Worth knowing

### PostgreSQL 18.6, 17.11, 16.15, 15.19, 14.24 — `postgresql.org`
Patch your databases. This release fixes **28 CVEs and over 110 bugs**, including several CVSS 8.8 heap buffer overflows (`to_char`, regexp, `pg_stat_statements`, `pg_dump`) and an arbitrary-code-execution issue in `psql`'s `\unrestrict`. Three of the bug fixes **require manual action after upgrading**, which is easy to miss: parallel GIN index builds could corrupt `reltuples` (check and re-analyze), `btree_gist` indexes on float or bit columns need a `REINDEX`, and `ltree` indexes with more than 14,653 labels need one too. Note that 18.5 was never shipped — 18.4 goes straight to 18.6 because of a regression. Separately, **PostgreSQL 14 stops receiving fixes on 12 November 2026**, so 14.24 is close to the end of the line.
📎 [Release announcement](https://www.postgresql.org/about/news/postgresql-186-1711-1615-1519-1424-and-19-beta-3-released-3365/)

### PostgreSQL 19 Beta 3 — `postgresql.org`
Shipped alongside the security release. Feature freeze is in effect, so the 19 feature set is now locked: **`REPACK`** (a unified, largely non-blocking table reorganisation command replacing the `VACUUM FULL` / `CLUSTER` / pg_repack tangle), **SQL/PGQ property-graph queries**, and temporal data handling via `FOR PORTION OF`. Beta 3 itself is fixes to temporal table syntax, logical replication and `postgres_fdw` query correctness. GA is expected around September–October — a good moment to start testing extensions against 19 if you depend on a lot of them.
📎 [Release announcement](https://www.postgresql.org/about/news/postgresql-186-1711-1615-1519-1424-and-19-beta-3-released-3365/)
